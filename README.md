# 小说状态工作台

一个本地优先的中文小说创作辅助工具。它不自动替作者连续生成正文，而是把正文、资料库、事件和角色认知整理成可验证、可继承的小说状态。

## 当前实现

- 书架：创建、编辑基础信息、搜索、删除，并按书籍隔离全部数据。
- 阅读器：章节 CRUD、TXT/Markdown 导入、中文字数统计、正文编辑、阅读位置字段、版本历史。
- 版本：每次保存生成新版本；字符级版本差异对比；后端提供旧版本恢复并生成新版本的接口。
- 资料库：角色卡、世界观/知识卡、历史版本、分类和搜索。
- 大纲：大纲版本与大纲块，支持目标、冲突、转折/结尾、章节范围。
- 分析：阅读器保留“分析本章角色”入口；新增 `Graphify 图谱` 工作区，支持章节审阅、从本章生成资料库更新提案，以及初始化角色、知识、事件和情节线。
- Graphify：支持初始化提案、审阅本章、更新资料库、故事状态、情节线新建/解决、关系查询、深度追踪和两点路径查询。资料库是当前事实源，关系图是从资料库和正文引用派生出的查询层。
- 可视化关系图：关系图按角色、知识、事件、情节线和章节形成可筛选社区，显示节点数量与关系数量；支持搜索、全选/取消全选、缩放、平移、拖动节点、点击节点查看详情并高亮关联关系。
- 入库：当前改为自动入库。无冲突且结构化的角色、知识、事件和情节线变更会在分析完成后直接写入并生成新版本；逐章审阅中带有明确标题的事件也会自动加入事件轴。冲突、无标题或无法结构化的结果会自动跳过。原始 LLM 响应、运行记录、变更状态和入库日志都会保留。
- 自动触发：服务启动时会自动补齐已有章节；新建章节、导入章节、保存正文新版本或恢复旧版本后，也会自动创建 Graphify 章节处理任务，不需要再手动点击“审阅”或“初始化”。任务按章节正文 SHA 去重：正文没有变化不会重复调用模型，正文发生变化才会再次提取并入库；运行状态可在 Graphify 页面顶部查看。
- 日志：Graphify 图谱页面提供“入库日志”，显示原值、写入值、来源、证据、原因、时间和执行结果。
- 设计参考：采用 `graphify-novel` 的“资料库作为事实源、关系图作为连接层”思路；分析结果会先保留原始记录，结构化且无冲突的资料会按当前自动入库策略写入，无法确认的内容不会强行写入。
- 事件轴：轻量 SVG 横向事件图，支持主线、支线、伏笔、人物线、世界线筛选；未知结束时间以开放端点显示。
- 提示词：阅读器可选择任意已有章节或下一章，聚合大纲位置、前两章全文、更早章节梗概、目标章节角色状态与角色关系，生成可复制到其他 LLM 的章节写作提示词。
- LLM：仅保留用于小说资料分析的 OpenAI Compatible 配置，支持启用开关、API Key 脱敏展示和连接测试。
- 导出：书籍 JSON、正文 TXT。

## 启动

在项目根目录执行唯一启动命令：

```text
python run.py
```

启动器会先检查后端健康接口和前端地址：

- 如果服务已启动，不会重复创建进程，只显示当前状态菜单。
- 如果服务未启动，只启动缺失的服务，等待就绪后显示状态菜单。
- 启动器只管理 NOVELTOOLS 后端与前端。
- 菜单支持刷新状态、启动缺失服务、停止本启动器管理的服务和打开前端页面。

服务日志保存在 `data/logs/backend.log` 和 `data/logs/frontend.log`。

然后打开：

- 前端：http://localhost:5173
- 后端文档：http://localhost:8000/docs

首次运行前请先执行依赖安装：

```text
python -m pip install -r backend/requirements.txt
cd frontend
npm install
cd ..
```

## LLM 配置

可选地在项目根目录 `.env` 设置数据库、数据目录和默认模型。界面中的“LLM 设置”可以添加多个 OpenAI Compatible 配置，填写 Base URL、模型名和 API Key 后启用。

未配置可用 API Key 时，分析仍可运行，但只产生本地保守的占位事实/事件结果，并明确提示作者。这是为了保证离线演示时不会把没有证据的推断伪装成分析结论。若只有一条已保存且有 API Key 的配置，即使忘记勾选“启用”，系统也会兼容性使用它；配置多条模型时仍需明确启用其中一条。

Gemini WebAI 和星月浏览器会话的运行、登录与状态控制已归属“我的 AI 工作台”。NOVELTOOLS 不再启动或配置这些服务，只保存小说资料并可选调用普通 OpenAI Compatible 接口完成资料分析。数据库中的历史 Provider 行和字段继续保留，但不会在 NOVELTOOLS 中展示或执行。

## 测试

后端：

```text
cd backend
set PYTEST_DISABLE_PLUGIN_AUTOLOAD=1
python -m pytest -q
```

前端构建：

```text
cd frontend
npm run build
```

Playwright 冒烟测试会自动启动独立的测试前后端，并使用 `test_data/playwright` 下的测试数据库，不会读写日常使用的 `data/noveltools.db`：

```text
npm run test:e2e
```

## 数据位置

- SQLite 元数据：`data/noveltools.db`
- 正文版本文件：`data/books/<book_id>/chapters/<chapter_id>/v<version>.txt`
- 上传与后续导出目录：预留在 `data/uploads`、`data/exports`

## 后续扩展

第一版选择了可维护的轻量实现：同步分析请求、SQLite、本地文件和自绘 SVG。后续可以在不改变核心数据模型的前提下增加 Alembic 迁移、后台任务队列、章节拖拽 UI、事件关系箭头、Markdown 报告导出、事实引用索引和更严格的 LLM JSON 重解析流程。

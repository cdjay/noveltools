# 独立章纲与正文关联

页面：`/books/{book_id}/chapter-plans`，可直接打开固定章纲：`/books/{book_id}/chapter-plans/{plan_id}`。

章纲先于正文存在，不会创建空白章节。名称、卷名、内容及草稿/确认状态保留独立版本；排序不改变章纲标识，也不重排已关联的正文。恢复旧版追加一个草稿版本，需重新确认。

## API

前缀：`/api/books/{book_id}/chapter-plans`。

| 方法与路径 | 用途 |
| --- | --- |
| GET `/` | 返回 `plans` 与可选 `guidance`（章纲共同说明资料的当前版本） |
| POST `/` | 创建章纲，字段 `title`、`volume`、`content`、`status`（draft/confirmed） |
| GET `/{plan_id}` | 章纲当前版本、正文关联、需复核状态、历史生成使用记录 |
| GET `/{plan_id}/versions` | 独立完整版本历史，包含版本 ID 和版次 |
| POST `/{plan_id}/versions` | 保存新版本，需 `base_version_id` 与正文同样的四个章纲字段 |
| POST `/{plan_id}/versions/{version_id}/restore` | 恢复为新草稿版本，需 `base_version_id` |
| GET `/{plan_id}/export.md` | 导出章纲及共同说明 |
| POST `/reorder` | `plan_ids` 为本书完整新顺序；`previous_order` 为读取时的完整旧顺序 |
| POST `/{plan_id}/binding` | `base_version_id`、`previous_chapter_id`、`chapter_id`；只能关联本书已有正文，null 解除关联 |
| POST `/{plan_id}/review` | 人工核对当前正文与章纲后提交 `base_version_id`、`chapter_version_id` |
| POST `/import-outline/move` | 显式迁移大纲末尾的章纲段，需 `base_version_id`、`section_heading`、可选 `volume` |

章纲以固定 UUID 标识，正文以固定 chapter ID 关联；不按标题或章节序号猜测匹配。一个正文最多关联一份章纲。删除正文解除当前关联；历史来源随对应正文版本删除，不指向其他章节。

## 生成与审核

- 旧书没有独立章纲时维持原有续写行为。
- 一旦本书存在章纲，生成按章纲顺序取第一份未关联正文的计划；不跳过草稿，章纲用尽即停止。启动前核对本次数量范围内所有计划均已确认。
- 有首章确认章纲时允许从零正文开始。第一章输入明确“尚无正文”，不将计划伪装为当前状态；保存后再生成梗概和状态速查。
- 正文输入新增 `chapter_plan`（含 `plan_id`、版本 `id`、版次、所属卷、题名与内容）及 `chapter_plan_guidance`。辅助整理不把未发生的章纲自动回填为事实。
- 模型调用前后核对全部章纲排序、当前版本、关联、共同说明版本与原有来源。来源变化则拒绝保存旧输入结果。
- 正文、关联和 `ChapterPlanUse` 来源记录在一个事务提交，断点继续不重复建章。手动关联不会伪造生成使用记录。
- 自动生成不等于逻辑审稿通过；显示“正文需复核”。人工核对后记录两侧版本，任一侧再次修改即重新提示。不会自动覆盖正文或反向修改章纲。
- 核对按钮记录人的核对结果，不提供自动语义审核保证。

## 迁移、备份与回滚

迁移只接受用户明确指定的大纲末尾章纲段（从第1章连续编号）；不对任意大纲自动猜测拆分。共同执行说明/勘误迁到书籍资料 `chapter-plan-guidance`，在章纲页面展示并随正文生成输入。迁移全部在一个事务中完成：追加章纲草稿、追加资料版本、追加只保留宏观规划及入口的大纲版本。原大纲历史完整保留。已有章纲或旧大纲基准版本不匹配时拒绝重复迁移。

书籍备份升级到格式版本4，包含章纲全部版本、当前关联、人工复核版本与生成来源记录；仍可导入版本1—3。恢复为新书时重新分配章纲标识并重映射正文/章纲版本引用。

本次数据库变更仅新增三个表，未改写历史兼容大纲块。应用代码回滚后新表仍留存，勿删除；内容回滚优先从迁移前书籍备份恢复为副本核验。只恢复旧大纲会同时出现旧章纲全文与独立章纲，不能把这种状态作为两份有效计划继续写作。

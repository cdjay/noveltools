# LLM 模块分流

LLM 配置分为“模型列表”和“模块分流”。分流按调用模块分别保存，跨书籍共用同一模块配置；不存在跨模块通用备用池；书籍备份不包含模型连接、密钥或分流，完整数据库备份包含这些配置。

## 当前模块

| 标识 | 功能 | 调用入口 |
| --- | --- | --- |
| `chapter_summary` | 单章梗概 | `POST /api/chapters/{chapter_id}/summary` |
| `batch_summary` | 批量梗概 | 持久化梗概任务创建、继续；兼容的 `POST /api/books/{book_id}/chapter-summaries` |
| `current_state` | 当前状态速查 | `POST /api/books/{book_id}/current-state/generate` |
| `chapter_writing` | 正文生成 | 持续生成正文任务，详见 [工作流接口](writing-workflow-api.md) |

连接测试和读取模型列表直接使用 URL 指定的配置 ID，不经过模块分流。正文生成默认选取已保存的 Gemini 模型配置，也可明确指定其他模型。正文、大纲、资料和配置保存不触发模型调用。

## 默认与指定配置

- 原 `LLMProvider.enabled` 字段保留兼容，现在在界面明确称为“设为默认模型”。仍最多一个默认模型，升级不更改现有选择。
- 正文生成默认匹配模型 ID 含 gemini 的有密钥配置，优先默认 Gemini，其次最近保存的 Gemini；无匹配则提示先配置。其他没有独立分流的模块使用有密钥的默认模型；若无可用默认配置，提示先配置，不任意选择其他模型。
- 指定分流可以使用任意有密钥的 OpenAI Compatible 配置，无需把它设为默认。切换默认模型不改变明确指定的分流。
- 删除指定配置时，数据库将路由的配置 ID 清空，但保留“明确指定”状态。模块提示失效，不自动跟随默认，避免删除后 ID 被重用时调用其他配置。清除密钥同样使其失效。
- `enabled: false` 表示非默认，不再表示禁止明确分流调用。要停用某配置，先将对应模块切换到其他模型；清除密钥也会使其无法用于后续请求。

## 读取与修改

`GET /api/llm/routes` 返回当前四个模块：

```json
[
  {
    "module": "chapter_summary",
    "label": "单章梗概",
    "description": "正文页生成或重新生成本章梗概。",
    "provider_id": 3,
    "use_default": false,
    "revision": 1,
    "error": null,
    "fallbacks": [],
    "effective_provider": {"id": 3, "provider_name": "整理模型", "model": "model-id"}
  }
]
```

`provider_id` 是配置 ID；模型配置列表仍通过 `GET /api/llm/providers` 读取，密钥不回显。没有已保存的分流时返回 `revision: 0`、`use_default: true`，GET 不写数据库。

`PUT /api/llm/routes/{module}`：

```json
{"provider_id": 3, "fallback_provider_ids": [4, 5], "base_revision": 0}
```

传入 `provider_id: null` 恢复跟随默认主模型。`fallback_provider_ids` 为当前模块的有序备用 ID，最多 3 个，`[]` 明确关闭兜底；旧客户端省略或传 null 时保留已有备用。重复、与当前主模型重复、缺少密钥或失效的配置返回 400；超过 3 个返回 422。读取的 `fallbacks` 按 position 排序，包含 provider_id、provider_name、model、error、cooldown；失效备用保留空 ID，防止删除后的 ID 复用。主模型的 effective_provider 也包含 cooldown（until 为 UTC 时间，reason 为安全分类），无冷却时为 null。

必须携带上次读取的修订号；成功返回该模块最新状态。并发旧修订返回 409；未知模块返回 404；指定配置不存在、类型不符或缺少密钥返回 400。失效指定配置的 `provider_id: null, use_default: false` 与正常默认模式不同，调用方不能只凭 ID 为空自行回退。

速查 `/context` 的 `model`、`max_output_tokens`、`timeout_seconds` 描述速查分流的主模型；生成版本的 model 才记录最终实际返回内容的模型。指定配置失效时返回 `provider_error`，仍返回来源资料统计，已有速查保持可读。

## 任务时机

单章梗概和速查在请求启动时选择模型。批量任务在创建时固定主模型及本模块备用的配置 ID、身份时间戳、模型和参数（不保存密钥），正在运行或排队的任务不因分流修改切换模型。停止后点击继续时读取最新批量分流；既有章节结果不会重复覆盖。兼容的同步批量接口也在请求启动时固定选择。

分流配置本身只分配模型，不触发生成。持续生成任务由正文页显式启动，不进行无限重试或跨模块模型轮转。保存分流无需等待正在运行的生成结束，修改作用于后续任务。

## 有序备用与停止条件

- 每个模块独立选择主模型 → 备用 1 → 备用 2 → 备用 3。没有备用就保留单模型行为，遇到错误停止；不会借用其他模块的备用，也不会临时寻找默认模型。所有已有分流升级时备用为空，不自动替用户选择模型。正文需固定 Gemini 时，保留 chapter_writing 的备用为空。
- HTTP 403、429 或错误体中明确的配额／用量窗口耗尽信号触发兜底，也识别以 HTTP 200 包装的额度错误。成功正文中提到额度不会触发。每个配置在同一次请求中最多尝试一次，原始提示词和全部资料不变，使用目标配置自己的地址、密钥、温度、输出上限和超时。
- 普通 HTTP 400、401、404、502、超时、无效正文／格式／截断、来源变化不会触发兜底。所有备用都受限或冷却时返回停止结果，已有正文、梗概及速查保留；不无限循环，也不等待五小时阻塞任务。
- 仅在启用备用的请求遇到受限时记录该配置冷却；后续启用备用的模块请求暂时跳过同一配置。只共享冷却状态，不共享备用选择。优先 Retry-After（秒或 HTTP 日期），其次绝对 Unix 时间的 x-ratelimit-reset / -requests / -tokens，最多采用未来 24 小时；未提供有效时间时冷却 5 分钟。不猜测模型额度恢复时刻。到期后下一次用户任务会重新优先主模型，不主动创建请求；换地址、模型或密钥会使旧冷却指纹失效。
- 快照固定备用顺序和参数，密钥按配置 ID 与创建时间验证后读取；接口地址变化会停止，避免旧地址收到新配置密钥。配置删除或密钥清除需修复分流后继续。旧任务没有备用快照，不会在运行中突然新增兜底；点击继续任务才载入新分流。
- 单章和速查保存实际模型，批量章节消息也显示实际模型。持续写作接口新增 `failover_events`（最近 100 条服务端持久化记录，id/time/text），浮窗显示触发原因、切换模型及返回结果，不记录原始模型错误体、提示词、正文或密钥。
- 批量梗概在一个章节失败且无法兜底时停止，失败章与未执行章留待手动继续，已完成章保留。兼容同步批量接口同样停止，results/total 只包含此次已处理章节。

## 最大输出与输入上下文

最大输出 Tokens 只限制回复长度，不是输入上下文容量。模型输出上限由各自服务决定，不适合一律设置为百万。Gemini 的已观察输出范围为 1～65,536 时，设置 1,000,000 会产生 HTTP 400；错误分类会提示具体输出上限，不触发换模型，也不截断输入。

## 复制模型配置

`POST /api/llm/providers/{provider_id}/copy` 无需请求体。复制已保存配置的 Base URL、API Key、模型、温度、最大输出 Tokens 和超时，创建名称带“副本”的独立配置，返回与模型列表相同的无密钥响应。原配置不存在或不是 OpenAI Compatible 类型时返回 404。没有密钥的配置也可复制，副本同样显示未设置密钥。

复制不改变默认模型或模块分流，副本固定为非默认。页面创建后直接选中副本，只改名称或模型名再保存即可；密钥由服务器复制，浏览器不读取原密钥。后续编辑、清除密钥或删除副本不会改动原配置。此接口不调用上游模型。

进入模型列表时优先选中默认配置，无默认时选中已有列表的第一项；只有没有任何配置或主动点击“新建”时显示空白连接表单，不预填示例服务地址或模型 ID。未保存的表单修改会禁用复制，切换配置时提供草稿保护。

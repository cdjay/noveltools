# 章纲续写

章纲页提供「章纲续写」，输入本次处理数量 1—100（默认 1）、工作流、可选卷名和本次要求。默认从末尾追加；选择「从指定章重新生成」可从已有位置开始，原章纲新增版本并保留标识、历史和正文绑定，超过末尾继续追加。不创建或覆盖正文。

重生成时仅使用起始位置之前的章纲；目标位置已有正文时提供该正文作为需要核对的旧稿，尚未写正文的旧章纲及后面章纲不混入输入。绑定正文须重新审核；重生成结果仍为章纲草稿。开始位置不可跳过空缺位置。暂停恢复按已保存进度继续。

每章独立执行：冻结资料 → 生成 → 审核 → 条件打回并修改 → 通过 → 保存章纲草稿 → 冻结包含新章纲的资料 → 下一章。循环次数由画布条件节点控制，默认最多修改三次。机器审核通过与作者确认分开。

首次选择默认工作流，基于现有正文生成和最终主编审核节点的模型配置创建本书独立章纲画布；原工作流不改动。未配置角色模型会报错。之后可选择保存的其他工作流或打开章纲画布修改。知识库默认选入本书所有已保存非空资料，可在画布调整。

资料包含全书大纲、前面所有独立章纲（不要求绑定正文）、共同说明、所选书籍资料与前文事实。较早正文有有效梗概时使用梗概，否则使用正文；最近五章使用全文。大纲只读，计划与已发生事实明确区分。来源不截断，超出模型容量时由调用报错并保留已完成章节。

## 接口

| 接口 | 行为 |
| --- | --- |
| GET `/api/books/{book_id}/plan-writing/settings` | 本书最近使用的工作流 |
| POST `/api/books/{book_id}/plan-writing` | `{chapter_count, start_position?, workflow_id?, volume?, requirements?}`；启动任务 |
| GET `/api/books/{book_id}/plan-writing/latest` | 最新任务 |
| GET `/api/plan-writing/jobs/{id}` | 数量、轮次、状态、已保存章纲列表 |
| GET `/api/plan-writing/jobs/{id}/source` | 本章冻结资料，供画布提取节点使用 |
| GET `/api/plan-writing/jobs/{id}/output` | 最后保留的候选稿或未通过的逐轮记录 |
| POST `/api/plan-writing/jobs/{id}/cancel` | 停止并保留已完成章纲 |
| POST `/api/plan-writing/jobs/{id}/resume` | 暂停后继续剩余章纲；提交结果不明或审核未通过时要求先核对 |

生成模型返回单章 JSON：`{"title":"章节名","volume":"所属卷","content":"完整章纲"}`。审核模型返回 `decision=pass/revise/needs_author` 及 `opinions`。仅接收条件节点审核通过的最终文本。

章纲及任务检查点原子保存，重查不会重复追加。生成期间大纲、前文章纲、书籍信息、所选资料或正文版本变化时，候选输出保留但不写入章纲。停止后可以重新生成未完成的当前章；已完成章节不重复生成。页面刷新、切换或关闭进度窗不停止后台任务。

同一本书的正文生成、审核和章纲续写互斥。服务重启时，已提交且有运行 ID 的任务只查询原运行；待执行任务暂停，提交结果不明则需核对画布，避免重复调用。新表为 `plan_writing_jobs`、`plan_writing_settings`，只做新增；任务记录仅本机保留，生成的章纲沿用现有版本历史及书籍备份。

验证：隔离 SQLite 的多章连续追加、下一章参考新章纲、来源冲突、停止恢复、数量限制和未通过不保存；浏览器验证数量选择、关闭窗口后继续、列表自动更新与窄屏布局。未使用真实模型生成用户小说。

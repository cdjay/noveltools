# 正文页审核、修订与确认

2026-09-10。正文页默认界面尺度提高到原来的约125%，浏览器100%即可使用。章节列表与正文共用纸面底色，未选章节仅一行；选中后展开状态与概要。右栏加宽，版本元信息及操作压缩，长来源备注折叠。1440px及以下默认收起右栏，900px及以下默认收起章节列表，可用工具栏按钮展开。

## 交互

1. 章纲“生成正文”：已有绑定直接打开该章，未绑定时创建带标题的空白正文。单章生成不再要求章纲先确认；持续生成原规则不变。
2. 工作流生成前检查所有启用的书籍／知识库提取节点是否勾选“仅从正文页传入”；未勾选返回409并列出具体节点，不创建任务、不启动前置记忆调用。
3. 正文“审核”：使用当前已保存版本调用西瓜章节审稿。书籍提取的bodyStart和bodyEnd都设置为当前章节编号A；前文独立发送，不混进待审正文。
4. 主编意见弹窗保留全文，M确定问题、M可选建议、Q待决定、K保护项按类型着色。文本可编辑，未提交意见暂存在浏览器。关闭弹窗不取消任务；返回同章可恢复状态。
5. 点击“修订”：将当前编辑意见和采纳补充传给正文修订。补充留空时自动采纳确定问题，有明确收益才采纳可选建议；未裁定Q不自行决定。2026-09-11按用户授权将默认画布改为全文修订：Gemini结合原稿、意见、采纳项、章纲、前文和资料库重新生成完整候选，revised-prose直接输出正文；GPT的revision-check复核完整候选。允许必要的场景重写、压缩和重新分段，保护剧情事实与回报，而非强制逐字保留。工作流完成后追加草稿版本，复核报告不写入正文；保留历史，不自动再次审核。
6. “确认正文”：一次操作将当前稿设为正式，并记录已核对当前章纲。之后正文新版本或章纲新版本需要重新确认。确认不调用模型、不产生重复正文版本；空白正文和过时版本不能确认。

## 接口

| 接口 | 参数与作用 |
| --- | --- |
| POST `/api/chapters/{id}/review` | `{base_version_id}`，启动单章审核 |
| POST `/api/chapters/{id}/revision` | `{base_version_id, review_job_id, opinions, decisions?}`，修订当前被审版本 |
| GET `/api/chapters/{id}/review/latest` | 本章最近的审核／修订任务 |
| GET `/api/chapter-review/jobs/{id}` | 任务状态、意见、附带复核报告 |
| POST `/api/chapters/{id}/confirm` | `{base_version_id, plan_version_id}`；无绑定时后者为null |
| POST `/api/workflow-writing/jobs/{id}/cancel` | 复用任务停止接口，并请求取消原画布运行 |
| GET `/api/workflow-writing/jobs/{id}/source` | 冻结的本章资料，供画布提取节点读取 |
| GET `/api/workflow-writing/jobs/{id}/output` | 保留的原始工作流输出，冲突时仍可取回 |

默认工作流由`review_workflow_id`、`revision_workflow_id`配置，分别指向现有“西瓜章节审稿”“正文修订”。意见输入使用`editorial-opinions`、`accepted-decisions`，若存在`author-requirements`，以本次补充替换其旧值。启动时检查节点存在、启用、类型及输入连线冲突。只传运行参数，不修改画布、模型、提示词或凭据。

## 保存与异常

- 使用正文版本、章节身份和资料清单约束审稿与修订。不把第一章旧意见应用到第二章，或把旧稿意见应用到新版本。
- 审核完成时和修订启动／保存时校验来源；发生变化则保留结果并拒绝自动覆盖。
- 本书生成、审核、修订互斥，跨书独立。提交状态在重启后标记为待核对失败，不自动重投；已返回run_id时只查询原运行。
- 提交及运行错误固定显示在弹窗底部、修订按钮旁，长篇意见滚动时仍可见。网络故障只重查原任务；审核／修订任务两小时仍未结束会停止本地等待并保留远端运行标识，不重投、不写正文。远端任务仍需在画布核对或停止。
- 默认全文工作流已移除正文合成节点，接口读取revised-prose完整正文。仍兼容用户另选的局部替换画布：有revision-apply时必须唯一启用，不回退读取JSON编辑计划。接口不提供自动语义正确性保证，复核有问题需再次修订，正式稿由用户确认。

## 验证

后端测试使用临时SQLite，浏览器测试使用独立前后端及测试库。覆盖A..A范围、编辑意见透传、默认采纳、指定正文出口、原稿历史保留、版本冲突、确认状态、重复绑定跳转、缺少勾选时启动前失败、宽窄布局和不自动再审。实际模型调用使用受控模拟，没有用用户正文发起测试生成。

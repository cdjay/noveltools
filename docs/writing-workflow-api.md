# 持续生成正文

正文工具栏提供“持续生成正文”入口，打开默认位于右下角的全局浮窗。浮窗提供 1 / 3 / 5 / 10 / 20 / 30 / 50 / 100 章选择与“开始生成正文”。这是本次新生成章节数量，不是目标章号。运行不依赖页面保持打开，刷新后可查看进度；不会因打开页面自动开始任务。

浮窗不使用遮罩，不锁定焦点，不占据工具栏布局；切换页面仍显示进度。可拖动标题栏、折叠为简化进度条或关闭；关闭不停止任务。进度条按完成正文、梗概与速查的归档章数计算，同时显示已保存正文数。窗口缩小时浮窗保持在可见范围内。错误在展开和折叠时均可见，运行转为失败或完成时提供提示。

步骤日志记录本浏览器窗口观测到的任务状态变化及观测时间，按任务区分，保留最近 100 条，刷新后从当前标签页的 sessionStorage 恢复；它不是服务端完整事件审计，页面未打开期间的中间步骤无法补录。已保存的任务章节继续通过接口读取。`model` 仅是正文模型，界面明确标注“正文模型”；梗概和速查分别使用任务快照中的对应模块分流。

任务推进时刷新章节列表与当前章节的梗概信息，保留正在编辑的正文和标题草稿；列表刷新失败会在后续轮询重试。

## 每章循环

1. 等待本书现有的梗概或速查任务结束。
2. 核对所有已保存章节，逐章补齐缺失或过时梗概。来源正文为空或缺失时停下，要求作者补充或恢复，不编造梗概。
3. 核对速查来源（大纲、正文版本、梗概等），缺失、空白或过时则重新生成并保存。
4. 发送最新速查全文、已保存大纲全文、书名、下一章编号给正文模型。输入不截断，未来大纲规划与已发生剧情明确区分。
5. 解析模型输出的 `title` 与 `content`，分别保存到章节名称和正文，创建正文版本。章节编号由服务按当前章节顺序计算，不由模型指定。
6. 补齐新章梗概，更新速查，再开始下一章。最后一章也必须完成这两个步骤，任务才算完成。

目前用于续写已有小说：启动前至少要有一章已保存正文及非空大纲。网页未保存的正文、大纲或提示词不参与模型请求。

## 模型选择

“LLM 配置 → 模块分流”新增 `chapter_writing`（正文生成）。没有单独指定时，选择模型 ID 含 `gemini` 且有密钥的 OpenAI Compatible 配置：优先默认 Gemini，其次最近保存的 Gemini；无匹配时提示配置，不自动换成普通默认模型。作者可明确指定其他模型。

工作流补齐及新章梗概使用 `batch_summary` 分流；速查使用 `current_state` 分流。启动时固定这三类模型的 ID、身份与参数，配置快照不含密钥；继续任务时读取最新分流。模型删除、密钥清除或接口地址变化时停止并要求重新配置，不悄悄更换模型。

正文输出约定：

```json
{"title":"章节名称","content":"完整正文第一段。\n\n完整正文第二段。"}
```

允许外围 JSON 代码围栏；字段必须是非空字符串，标题最多 200 字且不能跨行。无效 JSON、缺失字段、空输出和 `finish_reason: length` 均不创建新章节。调用使用所选模型的温度、输出 Tokens 和长任务超时。

## 持久化与停止

每本书同一时间最多一个持续生成任务，重复启动返回已有活动任务，不重复排队。单个工作进程依次执行正文任务，模型等待期间释放数据库写事务，停止接口与其他页面仍能响应。

“停止生成”在当前步骤完成后生效，保留已保存正文和进度；不会中断正在返回的模型请求。“继续生成”从最近检查点恢复，已保存的章节不会重复创建。正文与对应任务检查点在同一数据库事务中提交。生成期间大纲、正文、梗概或速查被修改时拒绝写入过时正文，提示核对后继续。

服务重启把未完成任务标记为 `interrupted`，等待手动继续，不自动续写。模型返回但尚未提交前发生进程中断，继续时可能重新调用模型；数据库中不会因此重复保存章节。已保存的任务章节被删除时不自动补造替代章节。

本功能未实现文风质量检查、对白复核或人物资料更新，生成成功不代表这些项目已验收。正文按 `draft` 保存，保留版本供作者审阅。

## 接口

| 方法与路径 | 用途 |
| --- | --- |
| `POST /api/books/{book_id}/writing-jobs` | 启动，JSON 为 `{"chapter_count":3}`，数量只接受上述八个选项 |
| `GET /api/books/{book_id}/writing-jobs/latest` | 读取最近任务，没有任务时返回 null |
| `GET /api/writing-jobs/{job_id}` | 读取指定任务 |
| `POST /api/writing-jobs/{job_id}/cancel` | 停止 |
| `POST /api/writing-jobs/{job_id}/resume` | 继续停止、失败或被中断的任务 |

响应包含 `id`、`book_id`、`status`、`step`、`message`、`model`、`target_count`、`saved_count`、`completed_count` 及章节进度 `items`，不返回密钥或模型原始错误正文。`saved_count` 表示正文已保存数，`completed_count` 表示正文、梗概与速查均完成数，二者可能不同。

步骤为 `preparing`、`waiting`、`summaries`、`state`、`writing`、`completed`；状态为 `queued`、`running`、`cancelling`、`cancelled`、`failed`、`interrupted`、`completed`。错误不自动重试或继续下一章。

已生成章节、正文版本、梗概和速查沿用现有书籍备份；任务运行记录只在本机数据库中保存，不随书籍便携备份恢复为待执行任务。升级前完整数据库备份包含任务进度。
